## SECTION 7 — KNOWN CONVERSION GAPS & AUDIT NOTES
## ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

GAP-01 | StartDate/EndDate as date slicer vs. Tableau parameter
─────────────────────────────────────────────────────────────
  Tableau PARAM-02 and PARAM-06 are discrete date parameters with
  specific defaults (2025-01-01 and 2025-12-31). In PBI these are
  implemented as a date range slicer on [Interaction Start Date].
  The slicer defaults cannot be enforced in the semantic model layer —
  they must be set in the report layer by the report author.
  Action: Set slicer default to 2025-01-01 / 2025-12-31 in report layer.
  Owner: Report author / PBI developer.


GAP-02 | PARAM-03 default "Region" vs. PBI Order=0 "Escalated Reason"
─────────────────────────────────────────────────────────────
  Tableau default for Escalated Axis = "Region". In PBI the field
  parameter table uses Order=0 = "Escalated Reason" as the first row.
  PBI visuals using this field parameter will default to "Escalated Reason"
  unless the report layer overrides the slicer default to "Region".
  Action: Set slicer default to "Region" in report layer if Tableau
          parity is required.
  Owner: Report author.


GAP-03 | PARAM-07 default "Finalized" vs. PBI SELECTEDVALUE fallback
         "All but Cancelled"
─────────────────────────────────────────────────────────────
  Tableau default for Status Parameter = "Finalized". PBI measures use
  SELECTEDVALUE('Status Parameter'[Status Parameter], "All but Cancelled")
  which means if no slicer selection is made the measure defaults to
  "All but Cancelled" not "Finalized".
  Action: Set slicer default to "Finalized" in report layer if Tableau
          parity is required.
  Owner: Report author.


GAP-04 | time_tracking__c stored as string in PBI
─────────────────────────────────────────────────────────────
  Tableau applies a custom date-parse-format to time_tracking__c:
  "HH 'Days' mm 'Hours' ss 'Mins'|...|yy 'Days'  'Hours'  'Mins'"
  PBI stores this column as string. No DAX parsing column was created.
  If any visual or measure needs to parse this column as duration/time,
  a new calculated column must be added.
  Action: Confirm with report owner whether time_tracking__c is
          actively used in any visual or measure.
  Owner: Report owner / data owner.


GAP-05 | qstn_cls_dt and reqt_dt stored as string in PBI
─────────────────────────────────────────────────────────────
  Both columns are stored as VARCHAR in the PostgreSQL source and loaded
  as string in PBI. No DAX date conversion column exists.
  If date filtering on these columns is required, a calculated column
  using DATEVALUE() or DATE(YEAR, MONTH, DAY) must be added.
  Action: Verify with data owner whether these strings conform to ISO
          date format before adding a conversion column.
  Owner: Data owner.


GAP-06 | Tier string matching uses Unicode en-dash (UNICHAR 8211)
─────────────────────────────────────────────────────────────
  The [Tier] and [Tier Sort] calculated columns use SEARCH("L1 –", ...)
  where "–" is a Unicode en-dash (U+2013). If source data uses an ASCII
  hyphen ("-") instead, the SEARCH() prefix will not match and all rows
  will return BLANK().
  Action: Run COUNTROWS(FILTER(..., [Tier] = BLANK())) on load and
          compare to expected escalation row count. If mismatch, update
          SEARCH prefix from "L1 –" to "L1 -" (ASCII).
  Owner: Data owner.


GAP-07 | [Reassignment reason group] Unicode SUBSTITUTE in TMDL
─────────────────────────────────────────────────────────────
  CC-33 uses UNICHAR(8211) and UNICHAR(8212) inside DAX SUBSTITUTE().
  DAX supports these Unicode code points. However, the TMDL file must
  be saved as UTF-8 without BOM to avoid encoding errors in Power BI
  Desktop when loading the TMDL. Do not save as ANSI or UTF-16.
  Action: Verify TMDL file encoding with a hex editor or Notepad++
          before importing.
  Owner: PBI developer.


GAP-08 | Auto-date hierarchy on multiple dateTime columns
─────────────────────────────────────────────────────────────
  The following source columns have auto-date hierarchy enabled in PBI
  (confirmed by presence of LocalDateTable_ entries in TMDL):
    Interaction Start Date, case_cls_dt, insert_ts, case_recv_dt,
    modf_ts, case_created_dt, case_closed_dt, start_time__c,
    end_time_mvn__c, rds_modf_ts, lst_rfr_dt,
    Interaction Start Date Date (CC-34)
  Each generates a hidden LocalDateTable_ table in the model.
  These are PBI-native and must not be manually edited.
  Action: Leave all LocalDateTable_ files as generated by PBI Desktop.
  Owner: PBI developer.


GAP-09 | Box plot measures (M-28 to M-37) — statistical accuracy
─────────────────────────────────────────────────────────────
  The box plot measures use TOPN/MAXX to compute Q1 and Q3 via integer
  position (INT(n*0.25)+1 and INT(n*0.75)+1). This is an approximation
  of the Tukey quartile method. Tableau may use a different interpolation
  for fractional positions. Results may differ slightly for small n.
  Action: Validate box plot output against Tableau for a known dataset.
  Owner: Report owner / data analyst.


GAP-10 | No relationships defined in this model
─────────────────────────────────────────────────────────────
  The semantic model contains no cross-table relationships. All multi-
  table DAX uses ALLEXCEPT, ALLSELECTED, REMOVEFILTERS, or TREATAS
  within a single table context. Parameter tables (PARAM-01 to PARAM-07)
  are not related to the main fact table — they are referenced only
  through SELECTEDVALUE() in measures and calculated columns.
  This is by design. Do not add relationships between parameter tables
  and the fact table.
  Owner: PBI developer.
