## 1. Document Purpose

This document is the complete migration knowledge base for converting the Tableau workbook "WMS Open Orders (3)" to the Power BI project "WMS OPEN ORDERS 2806". Every mapping in this document was extracted from and validated against the actual input and output files listed below.

| Item | Detail |
|---|---|
| Input (Tableau) | WMS Open Orders (3).json (converted from WMS Open Orders (3).twbx) |
| Tableau version | 2025.2.1 (document format 18.1), hosted on Tableau Cloud (us-east-1.online.tableau.com) |
| Output (Power BI) | WMS OPEN ORDERS 2806.pbip (WMS OPEN ORDERS 2806.SemanticModel + WMS OPEN ORDERS 2806.Report) |
| Semantic model format | TMDL (PBIP developer mode), import mode |
| Data platform | Snowflake (uscoldprod.east-us-2.azure.snowflakecomputing.com, warehouse BI, database CDW) |

### 3.2 Power BI Power Query (M) Partitions

All Tableau initial transformations (published data source semantics, blend preparation, and the open-orders scope) are implemented in Power Query as follows.

| Power BI Table | Mode | Power Query Logic (validated from TMDL partition) |
|---|---|---|
| V_Order_Status | Import | Value.NativeQuery against Snowflake CDW: SELECT of all 61 columns FROM "TRANSFORM"."V_ORDER_STATUS" with EnableFolding=true, then Table.SelectRows keeping only rows where [POSTED] = "N" (open, unposted orders) |
| V_Service_Metrics | Import | Value.NativeQuery against Snowflake CDW: SELECT FROM "MERCURYGATE"."V_SERVICE_METRICS" LEFT JOIN (SELECT * FROM CDW."USCOLD".DIM_WAREHOUSE WHERE ACTIVE_RECORD_INDICATOR = 'Y' AND DELETE_RECORD_INDICATOR = 'N') ON V_SERVICE_METRICS.WAREHOUSE_NUMBER = DIM_WAREHOUSE.WAREHOUSE_ID, EnableFolding=true |
| Date Selection | Import | Static embedded table (Table.FromRows over compressed JSON) with columns value (text) and Id (Int64); 6 rows |
| Table | Import | let Source = DateTimeZone.SwitchZone(DateTimeZone.UtcNow(), -4), then DateTime.ToText(DateTimeZone.RemoveZone(Source), "MM/dd/yyyy hh:mm tt") - produces the data refresh timestamp text (UTC-4) |

Key transformation decisions:

1. The Tableau published data sources were re-pointed directly at Snowflake using native SQL so folding is preserved.
2. The DIM_WAREHOUSE attributes that Tableau exposed inside the Logistics Service Metrics published source (family DIM_WAREHOUSE) are reproduced by an explicit LEFT JOIN with the active-record filter in the native query.
3. The open-orders business scope is enforced in Power Query with POSTED = "N" (in Tableau, POSTED was a data source/worksheet slice; every worksheet carried POSTED in its slices list).

## 6. Measures (Tableau Aggregations and Parameter Logic to Power BI DAX Measures)

The Tableau workbook contains no LOD expressions (verified: zero occurrences of FIXED/INCLUDE/EXCLUDE in the JSON). All aggregate-level Tableau logic (COUNTD, SUM, AVG shelf aggregations plus the parameter-driven Date Filter flag) was migrated to 12 DAX measures hosted in the dedicated Measure table.

A shared "Date Selection pattern" is embedded in most measures. It reproduces the Tableau Date Filter calculation exactly:

```
VAR SelectedOption = SELECTEDVALUE('Date Selection'[value], "Past Orders")
VAR TodayDate = DATE(YEAR(UTCNOW()), MONTH(UTCNOW()), DAY(UTCNOW()))
VAR FromDate = MIN('DateTable'[Date])
VAR ToDate = MAX('DateTable'[Date])
RETURN CALCULATE( <base aggregation>,
  FILTER('V_ORDER_STATUS',
    VAR RowDate = DATE(YEAR('V_ORDER_STATUS'[Date]), MONTH(...), DAY(...))
    RETURN SWITCH(TRUE(),
      SelectedOption = "Custom Dates" && RowDate >= FromDate && RowDate <= ToDate, TRUE(),
      SelectedOption = "Past Orders" && RowDate <= TodayDate, TRUE(),
      SelectedOption = "Future Orders" && RowDate > TodayDate, TRUE(),
      SelectedOption = "Today's Orders" && RowDate = TodayDate, TRUE(),
      SelectedOption = "Tomorrow's Orders" && RowDate = TodayDate + 1, TRUE(),
      SelectedOption = "All Open Orders", TRUE(),
      FALSE())))
```
