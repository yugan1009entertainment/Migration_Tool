## SECTION 6 — CONVERSION PATTERN CHEAT SHEET
## ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PATTERN-01 | Tableau data blend → PBI model relationship
─────────────────────────────────────────────────────────────
Tableau: Data blending between two datasources (left-join semantics,
         secondary datasource aggregated at link field level).

Power BI:
  relationship between tables on join key column.
  Use many-to-one cardinality (many rows in primary, one in secondary).
  Single filter direction (primary → secondary).

Example (this model):
  PRESENTATIONS_SLIDE_UNUSED_View_test (postgres)[Presentation Id]
  → presentations_used_slide_unused_view_test (postgres)[Presentation Id]


PATTERN-02 | Tableau LOD FIXED → DAX CALCULATE + ALLEXCEPT
─────────────────────────────────────────────────────────────
Tableau:
  { FIXED [Dim1], [Dim2] : COUNTD([Key]) }

Power BI:
  CALCULATE(
      DISTINCTCOUNT([Key]),
      ALLEXCEPT('Table', 'Table'[Dim1], 'Table'[Dim2])
  )

WHY: ALLEXCEPT removes all column filters except the named ones,
     replicating Tableau's FIXED scope.


PATTERN-03 | Tableau TOTAL() → DAX ALL() / ALLSELECTED()
─────────────────────────────────────────────────────────────
Tableau:
  COUNTD([Key]) / TOTAL(COUNTD([Key]))   -- removes one dimension from context

Power BI (all data):
  DIVIDE([Measure], CALCULATE([Measure], ALL([dim_column])))

Power BI (respects external slicers):
  DIVIDE([Measure], CALCULATE([Measure], ALLSELECTED([dim_column])))

Use ALL()         when denominator must ignore all filters on that dimension.
Use ALLSELECTED() when denominator must respect report-level slicers but
                  ignore the visual's cross-filter on that dimension.


PATTERN-04 | Tableau 2-level LOD → DAX nested AVERAGEX with SUMMARIZE
─────────────────────────────────────────────────────────────
Tableau:
  { FIXED [Dim1], [Dim2] :
    AVG({ FIXED [Interaction Id] : AVG([Value]) }) }

Power BI:
  AVERAGEX(
      SUMMARIZE('Table', 'Table'[Dim1], 'Table'[Dim2]),
      CALCULATE(
          AVERAGEX(
              VALUES('Table'[Interaction Id]),
              CALCULATE(AVERAGE('Table'[Value]))
          )
      )
  )

WHY: Outer SUMMARIZE creates the Dim1+Dim2 iteration context.
     Inner AVERAGEX per Interaction Id replicates the inner FIXED.


PATTERN-05 | Tableau string parameter → PBI NAMEOF field parameter
─────────────────────────────────────────────────────────────
Tableau:
  String list parameter with member aliases → dynamic dimension switching
  on visual axis (e.g., Country / Region / Sub Region / Product).

Power BI:
  DAX row constructor with NAMEOF():
  {
      ("Label A", NAMEOF('Table'[Column A]), 0),
      ("Label B", NAMEOF('Table'[Column B]), 1)
  }
  Column layout:
    [Display Label]   — user-facing slicer value
    [Fields]          — NAMEOF reference (ParameterMetadata kind=2, hidden)
    [Order]           — sort integer (hidden)
  Bind [Fields] column to the visual axis as a field parameter.

This model has TWO separate field parameter tables:
  View_by_email  — bound to email_ads_medex_view_test_2 columns
  view_by_Medex  — bound to PRESENTATIONS_ADS_MEDEX_view_test (2) columns


PATTERN-06 | Tableau ISNULL → DAX ISBLANK
─────────────────────────────────────────────────────────────
Tableau:
  ISNULL([field])

Power BI:
  ISBLANK([field])

Note: DAX ISBLANK() returns TRUE for both NULL and empty string "".
      If empty string ≠ NULL matters, use:
      [field] = BLANK() (NULL only) or LEN([field]) = 0 (empty string only).


PATTERN-07 | Tableau duration seconds → minutes conversion
─────────────────────────────────────────────────────────────
Tableau:
  AVG([duration_1]) / 60   or   AVG([totl_1]) / 60
  (duration_1 = slide duration in seconds; totl_1 = total duration in seconds)

Power BI:
  AVERAGEX(VALUES([Interaction Id]), CALCULATE(AVERAGE([duration_1]))) / 60

This pattern is used in: M-49, M-52, M-53, M-54, M-60.


PATTERN-08 | Tableau comment preservation in DAX

For every calculated column that originated from a Tableau expression, add:
  /* Original Tableau Expression is <formula> */
at the end of the DAX expression.
Use /// header comment for column display name:
  /// My Column Name - Column
These comments appear in Tabular Editor and VS Code TMDL view.

GAP-02 | [Approval date] String-to-Date Comparison Risk
  Severity : Medium
  Detail   : CC-06 [Date range] and CC-07 [Approval date 1] both rely on
             [Approval date] being a varchar column storing ISO-format dates
             (YYYY-MM-DD). If any rows contain non-ISO formats, comparisons

  Fix      : Verify the format of presn_apvl_dt in rpt_v.MV_RPT_VAULT_CNTT_PRESN_DTL.
             If format is non-ISO, add a SQL-level CAST to the M query (PQ-02).

  Severity : Medium
  Detail   : [Slides not used] in presentations_used_slide_unused_view_test
             is varchar/string. Direct SUM will fail. Any numeric aggregation
             requires INT() conversion:
             INT('presentations_used_slide_unused_view_test (postgres)'[Slides not used])
             Null/blank strings return 0 via INT() — confirm with data owner
             whether these should be 0 or excluded.
  Fix      : Add a DAX measure:
             measure 'Slides Not Used Count' =
             SUMX('presentations_used_slide_unused_view_test (postgres)',
                  INT('presentations_used_slide_unused_view_test (postgres)'[Slides not used]))
